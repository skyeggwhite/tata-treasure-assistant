独立桌面项目，使用 Python 标准库 Tkinter。双击启动器，先选择模拟器并点击“连接模拟器”，连接成功后再选择功能。右侧显示当前模拟器画面，约每 2.5 秒刷新；连接时检查 root 权限，未连接时操作按钮不可用。模拟器地址可手动填写，ADB 路径在“高级设置”中修改，连接配置自动保存到本地 `settings.json`。

黄色格子显示客户端模型记录的宝藏占地，其他格子暂显示“待判定”，不代表安全空地。支持每 10 秒刷新及 JSON 导出。营地寻宝不自动点击或挖掘；所有功能都不修改游戏内存。

## 挖萝卜（v8）

1. 在模拟器中进入挖萝卜奖励页面，暂不点击 GO。
2. 助手先连接模拟器，再选择“挖萝卜”，直接点击“开始自动探测”，无需提前读取地图。助手读取当前目标，通过普通 ADB 拖动地图瞄准，再点击 GO；确认找到后等待动画并读取下一个目标。
3. 如只想查看位置，可点击旁边的“只读取位置”。界面显示当前目标、瞄准点、剩余机会和找到数量。下方地图是游戏内部坐标示意，右侧为模拟器实际画面。
4. 点击“停止”或按 F9 停止。运行中不要手动移动地图或点击 GO，避免与自动操作冲突。

该活动一次只保存一个目标，找到后客户端再随机生成下一个，无法预览尚未生成的“全部萝卜位置”。当前实现每次探测前读取已经生成的目标。需要 root；自动点击只适配已测试的 9:16 竖屏。瞄准失败或 GO 未确认命中时停止，不重复盲点；失败时在本地 `diagnostics/` 保存错误信息和截图，不自动上传。

当前会话实测 6 次探测找到 6 个萝卜，其中首次用于校准验证，后续 5 次由连续自动流程完成，耗尽机会后正常停止。连续读取从约 9 秒优化到约 0.4 秒，首次定位仍约 11 秒。仅验证当前游戏版本和 MuMu 环境。

## 当前限制

- 需要模拟器 root，读取游戏进程 `/proc/PID/mem`。
- 自动读取 PID 和进程启动时间，进程变化后重新定位 LuaClient、LuaState 和寻宝实例，不再绑定固定 PID 或绝对地址。仅针对当前已验证游戏版本和 MuMu 的内存布局。
- 首次定位较慢，当前进程实测约 14 秒，后续刷新约 2–3 秒。模拟器重启后若 ADB 地址变化，需要修改界面中的模拟器地址。
- 已验证从零定位与连续刷新；实际重启游戏/模拟器后的完整流程尚未实测。游戏更新可能需要适配结构。
- 读取失败会清空地图，防止使用旧数据。
- 第一关一次宝藏预测已实际验证；第七关读取到完整 49 格及 5 件宝藏，但未逐格验证。炸弹位置尚未判定。

## 源码

`app.py` 为 UI，`reader.py` 为只读内存及 Lua 表解析；`radish_reader.py` 读取当前萝卜和相机，`radish_runner.py` 根据读取结果发送普通 ADB 拖动、点击。安装 Python 后可运行 `python app.py`，无需第三方运行时依赖。Windows 打包使用 PyInstaller。

```powershell
python app.py
```

自行打包：

```powershell
python -m pip install pyinstaller
python -m PyInstaller --onefile --windowed --name 塔塔寻宝助手 app.py
```

仓库仅提供源码，不包含游戏文件、调试转储或旧版本启动器。
